# Parity homes

Each directory is a template state dir (`ONCHAINOS_HOME` / `OCL_HOME`). The runner copies it fresh
for every run of both CLIs, so commands may write to it freely. Pick one with `"home": "<name>"`.

The `wallet*` homes are generated by `test/parity/make-home.mjs`
(`node test/parity/make-home.mjs` regenerates them; `--print` dumps every identity below).
They are real logins as far as both binaries are concerned (the runner sets
`ONCHAINOS_CREDENTIAL_STORE=file`, so upstream reads the same `keyring.enc`):

| file | content |
|---|---|
| `machine-identity` | fixed 64-hex identity = file-keyring password |
| `keyring.enc` | `{access_token, refresh_token, session_key}` encrypted with that identity (scrypt → AES-256-GCM, upstream `file_keyring.rs` format) |
| `session.json` | `saTeeId`, `sessionCert`, `encryptedSessionSk`, `sessionKeyExpireAt` (2100-01-01), fixed `deviceId` (so the `device-id` header is identical for both CLIs) |
| `wallets.json` | `parity@example.com`, project `parity-project-0001`, 3 accounts, `loginType` `google` |

Signing works end to end: `session_key` is a real X25519 secret and `encryptedSessionSk` is a real
HPKE seal (X25519/HKDF-SHA256/AES-256-GCM, info `okx-tee-sign`) of a fixed Ed25519 signing seed, so
`hpke_decrypt_session_sk` → Ed25519 signing (unsignedInfo / broadcast / sign-message / x402 flows)
produces deterministic signatures. JWTs are unsigned `HS256`-shaped tokens with `exp` 4102444800
(valid) or 1700000000 (expired); the server never sees them in fixture mode.

## Homes

| home | state | typical use |
|---|---|---|
| `anon` | empty | logged-out / anonymous commands |
| `wallet` | logged in, tokens valid, Account 1 selected | any authed wallet/payment/agent command |
| `wallet-expired` | access token expired, refresh token valid | first authed call POSTs `auth/refresh` (serve it with `wallet-common`) |
| `wallet-refresh-expired` | both tokens expired | stderr `Session expired…` + `session expired, please login again: onchainos wallet login` |
| `wallet-session-expired` | `sessionKeyExpireAt` in the past | `session expired, please login again…` without touching the keyring |
| `wallet-no-keyring` | wallets.json + session.json, no `keyring.enc` | credentials wiped |
| `wallet-account2` | logged in, Account 2 selected | selection-dependent output |
| `wallet-chains` | `wallet` + `chain_cache.json` with `updated_at` 4102444800 (never stale) holding the `wallet-common` chain list | chain-name resolution (`chain_profile::resolve`, `get_all_chains`) with **no** HTTP and no cache rewrite |
| `wallet-with-caches` | `wallet` + `cache.json`, `balance_cache.json`, `payment_cache.json`, `subscriptions.json`, stale `chain_cache.json`, `config.json` | logout / cache behaviour |
| `wallet-pending-login` | only a keyring with `pending_auth_session_id` = `7c1f0e2a-6b1d-4c3e-9a55-0d2f3b4c5d6e` and its X25519 key (as left by `wallet login --phase init`) | `wallet login --phase poll` |
| `wallet-login-pending` | `wallet` logged in as `previous.user@example.com` + the same pending login | re-login / account switch |
| `wallet-pending-two` | `wallet-pending-login` + a second pending key for `0b9e8d7c-6a5b-4c3d-8e2f-1a0b9c8d7e6f` | `poll --session-id <other>` (keeps the newest pending pointer) |
| `wallet-bad-wallets-type` | `wallet` with a hand-edited `wallets.json` (`"isNew": "yes"`, `"email": 5`) | serde_json streaming errors: document order + `at line L column C` |
| `wallet-bad-wallets-null` | `wallets.json` = `null` | JSON null is a parse error, not "not logged in" |
| `wallet-bad-wallets-dup` | `wallets.json` with a duplicate `email` field | `duplicate field` error |
| `wallet-bad-wallets-missing` | `wallets.json` whose address entry lacks `address` | `missing field` positioned after the closing `}` |
| `wallet-seq-wallets` | `wallets.json` = `[]` | serde seq-form struct (all fields default) → `account not found` |
| `wallet-bad-session` | `session.json` truncated | `EOF while parsing a value at line 1 column 22` |
| `wallet-bad-chain-cache` | `chain_cache.json` with `"updated_at": "1"` | i64 type error from the chain cache |

`node test/parity/make-home.mjs --only a,b` regenerates just the named homes.

## Masking notes

- `wallets.json.accountsMap`, `balance_cache.json.accounts` and the keyring blob are Rust `HashMap`s:
  upstream writes their keys in random order, so any case where upstream rewrites them needs a mask.
- `balance_cache.json` / `chain_cache.json` carry wall-clock `updated_at` fields.
- `keyring.enc`, `machine-identity`, `audit.jsonl` are compared as `<present>` only.
- Known harness gap: `canon.mjs` splits mask paths on every `.`, so `home.wallets.json.accountsMap`
  style masks never apply (file names contain dots). Until that is fixed the cases that rewrite a
  multi-account `accountsMap` or a timestamped cache report `[home]` diffs that are order/timestamp only.
